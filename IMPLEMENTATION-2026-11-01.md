# Atlantic Home: оновлення для конвектора

Реалізовано 1 листопада 2026 року. Обсяг уточнено власником: працюємо тільки з Atlantic; MYCOND і вологість не показуємо.

## Що змінено

- Один активний CSS-шар, системні шрифти, читабельні контрастні кольори, адаптивний desktop/sidebar і mobile/bottom navigation.
- Чотири екрани: Дім, Розклад, Енергія, Налаштування. Посилання на вкладки, reload і Back зберігають відповідний розділ.
- Звичайний і збільшений текст із локальним збереженням вибору. Попереднє налаштування заборони масштабування viewport залишено відповідно до побажання власника.
- Поточні покази не підміняються нулями. Немає вигаданих вологості, напруги чи миттєвих ватів. Середня потужність підписана як середня за інтервал.
- Вибір цілі з кроком 0,5 °C, швидкі значення 18/20/22/24, явна кнопка застосування. Значення, яке підтвердив пристрій, показано окремо від вибору користувача.
- Команда має стани надсилання, прийняття хмарою, підтвердження показами, помилки або відсутності підтвердження. Журнал показує команди поточної відкритої сесії.
- Перемикач вбудованого PROG/ручного режиму; перегляд отриманих даних програми за днями.
- Спільне серверне поновлення токенів для браузера і збору. Lease у БД захищає refresh від одночасних запитів різних serverless-процесів; compare-and-swap не дозволяє перезаписати нове підключення старим refresh.
- Поновлення токена прив’язане до connectedAt поточної браузерної сесії. Доступ попереднього підключення не переноситься на новий акаунт мовчки.
- Короткий серверний кеш Overkiz connection/setup на ключ токена, унікальні URL датчиків, один клієнтський координатор зчитування, пауза прихованої вкладки, послідовні запити, backoff і скасування запитів.
- Технічна діагностика та дорогі добові consumptions завантажуються лише на запит. Прибрані зайві зондування п’яти API під час підключення.
- Збір зберігає останній початок, успіх і помилку. UI відрізняє конфігурацію від реального успішного запуску.
- Фонові credentials зберігаються зашифрованими з явною політикою TTL; чинні cookie та старі записи сумісні. Runtime-схема створюється одним транзакційним запитом. Ідемпотентний SQL також збережено в db/001-atlantic-schema.sql.
- Захист від частих входів: 12 спроб за 10 хвилин на хеш адреси та область авторизації; Neon забезпечує узгодження між інстансами. Без Neon доступний локальний fallback для окремого процесу.
- Енергооблік у Europe/Kyiv, обробка літнього/зимового часу, пропусків, скидання та аномалій лічильника. API бере один показ перед початком періоду для правильної бази.
- Інтерактивний графік 7/30 днів із рідшими підписами осі, деталями дня, доступною таблицею та CSV. Немає даних і нульове споживання розрізняються; довгі паузи позначені.
- Тарифи та пристрій зберігаються явною дією користувача, а не конкурентним автозбереженням кожного символу. Пізнє завантаження не перекриває розпочате редагування. При недоступній хмарі залишається локальна копія.
- Встановлення PWA: PNG-іконки, стабільний id, shortcuts; безпечна offline-сторінка без приватних даних. Не кешуються захищений HTML/API або команди. Оновлення активується кнопкою користувача.
- CI використовує npm ci, Node 22, lint, тести й build.

## Перевірки

- npm run lint, npm run build, git diff --check — проходять.
- 19 автоматичних тестів: відсутні покази; часовий пояс; межі дня/ночі; DST; паузи; скидання й аномалії; середня потужність; тарифні пороги; порожній місяць; поновлення, відкликання, конкурентність і збереження токенів.
- npm audit: 0 відомих вразливостей на момент перевірки.
- Чотири екрани на 320/390/768/1280 px: без горизонтального виходу перевірених елементів у локальній імітації. Збільшений текст також перевірено на 320 px і після reload.
- На локальному адаптері Cozytouch: вхід, підключення, зміна 22 → 22,5 °C, PROG, підтвердження, блокування й повторний вхід без втрати підключення.
- Тестовий upstream-адаптер лежить поза репозиторієм і не публікується. Фізичному конвектору під час перевірок команди не надсилалися.

## Що ще потребує наступної роботи

- Редактор запису тижневої програми потребує перевірки реальної capability/схеми конкретного конвектора. Поточний UI цього не обіцяє.
- Серверний журнал команд, історія температури, таймери повернення режиму, сповіщення, бюджет і сімейний доступ потребують окремої реалізації; журнал цього випуску зберігається лише у відкритій вкладці.
- Немає польових Core Web Vitals або вимірювання фізичного часу реакції конвектора. Успішні build і тести не є доказом доступності Atlantic Cloud.
- Точний розподіл споживання всередині інтервалу невідомий: алгоритм явно позначає оцінку; пропуски понад 45 хв виділяє окремо.
- GitHub Actions не гарантує точного інтервалу; UI тепер показує реальні затримки. Новий heartbeat з’явиться після першого cron-запуску оновленої версії.
- Старий нечитабельний/відкликаний токен неможливо відновити без перепідключення. Новий refresh працює, якщо Atlantic надав чинний refresh token і Neon доступний.
- Підключення кількох фізичних конвекторів та незалежний від energyHistoryId homeId залишаються наступним етапом моделі дому. Цей випуск призначений для одного конвектора власника.
